# Модельная студия

Desktop-приложение для локальных LLM: запуск моделей, чат с изображениями, OpenCode, измерения и подбор настроек. Python + PySide6 / Qt Quick; данные хранятся локально в SQLite.

## Запуск

**Откройте `Запустить.pyw` или `Студия.pyw`.** Лаунчер использует `.venv` рядом с проектом и не зависит от имени рабочей папки.

Локальная Windows-сборка: **`dist/ModelStudio/ModelStudio.exe`**, создаётся по [инструкции сборки](docs/BUILD.md). В Git бинарники не хранятся. Для переноса копируйте весь каталог `ModelStudio`, включая `_internal`. Python отдельно ей не нужен. Модели, Ollama, llama-server и OpenCode устанавливаются отдельно.

После сборки `tools/create_shortcuts.ps1` создаёт фирменные ярлыки на рабочем столе и в папке проекта; команда — в [BUILD.md](docs/BUILD.md#application-icon-and-shortcuts).

При первом запуске из исходников импортируются настройки прежнего измерителя рядом с проектом. В готовой сборке прежнюю папку выбирают явно: **Настройки → Импортировать**. Исходные файлы сохраняются.

## Ежедневная работа

1. В **Моделях** добавьте GGUF-файл/папку либо подключите Ollama в настройках. Для GGUF укажите `llama-server.exe`.
2. В **Запуске** выберите модель и контекст; нажмите **Запустить модель**. Изменение параметров в форме не меняет уже работающую сессию.
3. Откройте встроенный **Чат** либо выберите папку проекта системным диалогом и нажмите **Открыть OpenCode**.
4. В **Исследовании** запустите быстрый тест, подбор режимов или отдельное сравнение MTP. Предварительный запуск модели не нужен: исследование само переключает конфигурации, затем восстанавливает исходную сессию или выгружает свою модель. Результаты сохраняются автоматически.
5. **Выгрузить** освобождает модель. Удаление файла модели сохраняет её историю в архиве.

Рекомендации появляются только при наличии сопоставимых проверенных замеров из полной истории выбранной модели; число загруженных карточек истории на них не влияет. «Нет данных» означает отсутствие измерения, а не нулевую нагрузку. RAM системы, память GPU и буферы модели показываются отдельно.

## Исследования и отчёты

- **Новое исследование** — единый конструктор контекст × память × MTP.
  Одно значение фиксируется, несколько дают все сочетания. Выбирайте отдельно
  агентский сценарий и проверку длинного входа.
- **Общие условия** относятся только к исследованию. Настройки запуска копируются
  явно и после этого меняются независимо.
- **Использовать готовые результаты** включено по умолчанию. Сценарий и длинный
  вход переиспользуются независимо при доказанной сопоставимости. Снимите отметку
  для нового измерения; прежние результаты сохраняются.
- **Посмотреть план** показывает каждое сочетание, источники готовых проверок и
  точное число новых. До 256 сочетаний; превышение объясняется без обрезки списка.
- **Результаты → Копировать**: итог исследования, актуальная сводка модели,
  полная история или выбранный замер. **Сохранить…** записывает Markdown/TXT.
  Папка отчётов открывается отдельной кнопкой.
- **Использовать для запуска** переносит настройки и сохранённый runtime-профиль
  с дополнительными аргументами. Если профиль удалён, приложение объясняет причину.
  Сервер запускается отдельно.
- Остановленное исследование можно продолжить из списка заданий. Уже завершённые
  проверки этого задания сохраняются, даже если использование прежних результатов
  отключено: отмена между длинным входом и сценарием не требует повторять длинный вход.

Основной тест производительности — **агентский сценарий** для llama.cpp:
6 коротких генераций по 128 токенов, история растёт от 4K до 24K.
Сравнивайте **время сценария в секундах: меньше — лучше**. По умолчанию один
повтор; при близких результатах можно выбрать несколько повторов, тогда
показывается медиана. Нужен контекст 32K или больше. В Ollama эта методика
пока недоступна.

Инструменты не запускаются: результаты чтения файлов и проверок заранее
заданы. Продолжения ассистента в истории также фиксированы, поэтому изменение
KV или MTP не меняет входы следующих ходов. Качество ответов не оценивается.
Перед каждым повтором первый вход обрабатывается без кеша; следующие ходы
переиспользуют общий префикс. Прогрев и запуск сервера не входят во время сценария.
Размер активной истории одинаков при 32K, 64K и большем выделенном контексте.
Это сравнение конфигураций одной модели, а не рейтинг интеллекта моделей.

Прежние замеры сохранены в истории и подробных отчётах, но не участвуют в
рекомендациях и не засчитываются как готовые агентские тесты. Для продолжения
задания со старой методикой создайте новый план: отдельные совместимые проверки
полного контекста могут быть использованы повторно.

## Изображения в чате

Для GGUF-модели откройте **Запуск → Настроить вручную → Изображения → Выбрать…**, укажите совместимый файл `mmproj.gguf`, включите переключатель и запустите модель. Назначенный файл запоминается для этой модели. В библиотеке mmproj находятся в фильтре **Вспомогательные**, отдельно от языковых моделей.

В **Чате → Картинка** выберите PNG/JPEG: до четырёх файлов на сообщение, до 10 МиБ и 16 мегапикселей каждый. Поддержку изображений подтверждает сам сервер. Для Ollama отдельный mmproj не нужен — возможность зависит от выбранной модели. Вложения копируются в данные приложения и сохраняются с перепиской.

## Данные и восстановление

`%LOCALAPPDATA%/ModelStudio`: `studio.db`, `reports`, `logs`, `backups`, `cache`, `attachments`. Переименование проекта не перемещает эти данные. Резервная копия и восстановление доступны в настройках. Формат `.studio-backup` включает БД и изображения из переписок. При восстановлении предварительно сохраняется копия текущих данных; прежние `.db` тоже поддерживаются. Запущенные задачи после аварийного закрытия помечаются прерванными; исследование продолжается только по команде пользователя.

## Разработка

Python 3.11+; проверено на Windows с Python 3.14.7.

```powershell
py -3.14 -m venv .venv
.venv\Scripts\python.exe -m pip install -e .
.venv\Scripts\python.exe -m model_studio
.venv\Scripts\python.exe -m unittest discover -s tests -q
```
