# Модельная студия

Desktop-приложение для локальных LLM: запуск моделей, чат с изображениями, OpenCode, измерения и подбор настроек. Python + PySide6 / Qt Quick; данные хранятся локально в SQLite.

## Запуск

**Откройте `Запустить.pyw` или `Студия.pyw`.** Лаунчер использует `.venv` рядом с проектом и не зависит от имени рабочей папки.

Локальная Windows-сборка: **`dist/ModelStudio/ModelStudio.exe`**, создаётся по [инструкции сборки](docs/BUILD.md). В Git бинарники не хранятся. Для переноса копируйте весь каталог `ModelStudio`, включая `_internal`. Python отдельно ей не нужен. Модели, Ollama, llama-server и OpenCode устанавливаются отдельно.

После сборки `tools/create_shortcuts.ps1` создаёт фирменные ярлыки на рабочем столе и в папке проекта; команда — в [BUILD.md](docs/BUILD.md#application-icon-and-shortcuts).

При первом запуске из исходников импортируются настройки прежнего измерителя рядом с проектом. В готовой сборке прежнюю папку выбирают явно: **Настройки → Импортировать**. Исходные файлы сохраняются.

## Ежедневная работа

1. В **Моделях** добавьте GGUF-файл/папку либо подключите Ollama в настройках. Для GGUF укажите `llama-server.exe`.
2. В **Запуске** выберите модель и контекст; нажмите **Запустить модель**. Изменение параметров в форме не меняет уже работающую сессию.
3. Откройте встроенный **Чат** либо выберите папку проекта системным диалогом и нажмите **Открыть OpenCode**.
4. В **Исследовании** запустите быстрый тест или ограниченный подбор настроек. Предварительный запуск модели не нужен: исследование само переключает конфигурации, затем восстанавливает исходную сессию или выгружает свою модель. Результаты сохраняются автоматически; отчёт можно скопировать, экспортировать в TXT/JSON и открыть его папку. В истории **Скопировать все отчёты** объединяет результаты выбранной модели по текущим фильтрам, включая ещё не загруженные строки. Кнопка **Скопировать исследование** в строке задания копирует весь прогон с параметрами, ошибками и причиной завершения; нажатие на само задание открывает его замеры. **Скопировать выбранный** оставляет возможность взять один замер.
5. **Выгрузить** освобождает модель. Удаление файла модели сохраняет её историю в архиве.

Рекомендации появляются только при наличии сопоставимых проверенных замеров. «Нет данных» означает отсутствие измерения, а не нулевую нагрузку. RAM системы, память GPU и буферы модели показываются отдельно.

## Изображения в чате

Для GGUF-модели откройте **Запуск → Настроить вручную → Изображения → Выбрать…**, укажите совместимый файл `mmproj.gguf`, включите переключатель и запустите модель. Назначенный файл запоминается для этой модели. В библиотеке mmproj находятся в фильтре **Вспомогательные**, отдельно от языковых моделей.

В **Чате → Картинка** выберите PNG/JPEG: до четырёх файлов на сообщение, до 10 МиБ и 16 мегапикселей каждый. Поддержку изображений подтверждает сам сервер. Для Ollama отдельный mmproj не нужен — возможность зависит от выбранной модели. Вложения копируются в данные приложения и сохраняются с перепиской.

## Данные и восстановление

`%LOCALAPPDATA%/ModelStudio`: `studio.db`, `reports`, `logs`, `backups`, `cache`, `attachments`. Переименование проекта не перемещает эти данные. Резервная копия и восстановление доступны в настройках. Формат `.studio-backup` включает БД и изображения из переписок. При восстановлении предварительно сохраняется копия текущих данных; прежние `.db` тоже поддерживаются. Запущенные задачи после аварийного закрытия помечаются прерванными; исследование продолжается только по команде пользователя.

## Разработка

Python 3.11+; проверено на Windows с Python 3.14.7.

```powershell
py -3.14 -m venv .venv
.venv\Scripts\python.exe -m pip install -e .
.venv\Scripts\python.exe -m model_studio
.venv\Scripts\python.exe -m unittest discover -s tests -q
```
