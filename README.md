# LLM Meter — Ollama и llama.cpp

Откройте **Запустить.pyw**, выберите источник и модель, нажмите **Запустить тест**.
Файл `.pyw` запускает окно без консоли. Старый `Запустить.cmd` тоже запускает `.pyw`
и сразу закрывается; для запуска без вспышки консоли используйте `.pyw` напрямую.
Нужны Python 3.10+ с Tkinter и установленный backend; pip-зависимостей нет.
Измеритель не скачивает модели. Ollama запускается отдельно; llama-server можно
запускать и перезапускать прямо из интерфейса.

Для установленного Bonsai: откройте **Запустить.pyw**, выберите **llama.cpp**,
**Ternary-Bonsai-2-27B-PQ2_0.gguf**, контекст **128K** и нажмите **Запустить тест**.
Нужный llama-server будет запущен автоматически. GGUF с `mmproj` остаётся видимым
во вкладке «Модели» как вспомогательный файл, но не предлагается для теста.

## Подключение

- **Ollama**: `http://127.0.0.1:11434` либо `OLLAMA_HOST`; список из `/api/tags`.
- **llama.cpp**: `http://127.0.0.1:8080`; список из `/v1/models`. Допускается адрес
  с `/v1` на конце. В обычном режиме сервер обслуживает одну модель, router — несколько.
  Если автосписок недоступен, имя/alias модели можно ввести вручную.
- Адреса backend, контекст, путь сервера и папки моделей сохраняются в `settings.json`.

llama.cpp использует `/v1/chat/completions`, SSE и нативные `timings`. Без timings
будет ошибка, а не подмена скорости генерации скоростью HTTP-запроса.
Поддержка не привязана к Bonsai; сервер должен поддерживать формат выбранной модели.

### Управляемый llama-server

Если `llama-server.exe` и папка GGUF обнаружены, выбор backend **llama.cpp** сразу
показывает локальные модели и включает запуск из LLM Meter. В списке видно имя файла;
его полный путь используется для запуска. Во вкладке **Модели** также можно выбрать
GGUF и нажать **Выбрать для теста**. Либо выберите
backend **llama.cpp**, включите **Запускать из LLM Meter**, укажите `llama-server.exe`
и нажмите **Открыть GGUF…**. Установка `~/Bonsai-demo` обнаруживается автоматически,
если она есть при первом запуске. Для других установок доступны выбор exe и папок.
Используется выбранная совместимая сборка; отдельной логики для Bonsai/Prism нет.

Выберите **Контекст**: 32K / 64K / 96K / 128K либо **Свой** (целое число токенов).
Нажмите **Начать тест**: приложение запускает сервер с `-c N -np 1 -ngl 99 -lv 4`,
проверяет путь модели и фактический лимит, затем проводит прежний тест.
При смене модели, контекста, exe или адреса собственный сервер перезапускается.
Для модели с отдельной сборкой можно назначить **runtime-профиль**: свой полный путь
к `llama-server.exe`, дополнительные аргументы и ожидаемые возможности. Привязка
делается к полному пути GGUF, не к совпадению имени в коде. Обычные GGUF без профиля
по-прежнему используют общий `server_exe` и прежние параметры. Выбранный runtime
показан под моделью; подтверждённое MTP показано после замера.

Локальный файл `runtime_profiles.local.json` (не отправляется в Git) хранит эти
привязки независимо от основных настроек. Пример для любой модели с MTP:

```json
{
  "runtime_profiles": {
    "my-mtp": {
      "name": "Prism MTP",
      "executable": "C:\\path\\to\\patched\\bin\\llama-server.exe",
      "extra_args": ["-fa", "on", "--jinja", "--spec-type", "draft-mtp", "--spec-draft-n-max", "2"],
      "capabilities": ["mtp"]
    }
  },
  "model_profiles": {
    "C:\\models\\my-model.gguf": "my-mtp"
  }
}
```

Все DLL runtime должны оставаться рядом с EXE. Если профиль объявляет `mtp`,
LLM Meter требует положительный `timings.draft_n` в измеряемых ответах; без него
тест завершается ошибкой, а не помечается как MTP. В JSON сохраняются `draft_n`
и `draft_n_accepted` каждого замера. Профиль и его аргументы входят в ключ
перезапуска управляемого сервера.

**Abliterated Bonsai 2 PQ2_0 MTP.** [Карта именно этой модели](https://huggingface.co/BoldingBuilds/Ternary-Bonsai-2-27B-Abliterated-PQ2_0-MTP-GGUF)
требует PrismML llama.cpp `prism-b10687-5d80cff` с
`0001-qwen35-mtp-hadamard-inverse.patch`: MTP-граф должен восстанавливать
Hadamard-базис после lookup embeddings. Для CUDA на этом компьютере отдельно
установлен [совместимый готовый Windows runtime ProCreations](https://huggingface.co/ProCreations/Ternary-Bonsai-2-27B-MTP/blob/main/runtime/WINDOWS.md)
в `runtimes/prism-mtp/`. Это самостоятельная патченная сборка
`d8f26eec-bonsai-mtp`, **не** указанная в карте сборка точного тега. Её совместимость
подтверждена загрузкой данного GGUF и положительными счётчиками MTP в реальном ответе.
Исходный `~/Bonsai-demo/bin/cuda/llama-server.exe` не менялся. Бинарные файлы runtime
не хранятся в Git; для повторной установки архив
`runtime/llama-bonsai-mtp-windows-cuda13.3-x64.zip` находится в репозитории
ProCreations, SHA-256: `d3bb0ed40defdf854463029dc37e16d2aa53ec779ab999d2bd0163588a329c00`.
Распакуйте весь архив в `runtimes/prism-mtp/` и укажите его EXE в профиле.
Контекст 128K может потребовать больше VRAM, чем доступно на конкретной карте;
при неудачной загрузке приложение покажет ошибку и позволит выбрать меньший.
По умолчанию управляемый сервер слушает `127.0.0.1:8081`; занятый чужим процессом
порт выдаёт ошибку. **Выгрузить сервер** освобождает его память. При обычном закрытии
LLM Meter собственный сервер также останавливается.

Загрузка ограничена 120 секундами, доступна кнопка **Остановить**. При ошибке/OOM/
неподтверждённом контексте процесс останавливается; можно сразу выбрать меньший
контекст. Причина и путь к логу показаны в интерфейсе. Логи сохраняются в `results/`.

### Внешний llama-server

Отключите **Запускать из LLM Meter** и введите адрес. Пример самостоятельного запуска:

```powershell
.\llama-server.exe -m "C:\models\model.gguf" -c 32768 -np 1 -ngl 99 --port 8080 -lv 4 --log-file "server.log"
```

Сборки/модели могут требовать своих параметров. Если timings отключены, в сборке,
поддерживающей этот флаг, включите `--perf`.

## Методика и метрики

Прогрев до 16 токенов, затем **3 замера по до 512 output-токенов**. Сохранены
прежнее задание и префиксы Warm up / Trial 1–3. Одинаковы temperature=0, seed=42,
лимит генерации и пользовательский запрос. Шаблоны чата, thinking и остальные
параметры берутся из модели/сервера и могут различаться. Thinking входит в счётчики.
Итог — медиана трёх замеров и min–max, без прогрева. Досрочный EOS отмечается.

| Метрика | Ollama | llama.cpp |
| --- | --- | --- |
| Генерация, ток/с | eval_count / eval_duration | timings.predicted_n / predicted_ms |
| Prompt всего | prompt_eval_count | usage.prompt_tokens |
| Prompt обработано | всего минус prompt_eval_cached_count | timings.prompt_n |
| Prompt из кеша | prompt_eval_cached_count | timings.cache_n либо usage |
| Prompt, ток/с | обработано / prompt_eval_duration | prompt_n / prompt_ms |
| Output | eval_count | usage.completion_tokens либо predicted_n |
| TTFT / первый фрагмент | таймер клиента | таймер клиента |
| Context limit | /api/ps.context_length | /props, runtime meta.n_ctx либо одинаковый n_ctx всех slots |
| Квант | /api/show.details | /props.model_ftype, meta.ftype, затем проверенный лог |
| Размер модели | /api/tags.size, размер на диске | meta.size, размер тензоров |

Длительности приводятся к секундам. TTFT: от начала запроса, включая соединение,
до первого непустого текста/reasoning; chunk с ролью не считается ответом.
Фрагмент может содержать несколько токенов: это не аппаратный таймер токена.
Медианы TTFT и prompt-speed показаны в карточках, исходные времена сохранены в JSON.

llama.cpp получает cache_prompt=false. Ollama управляет кешем автоматически.
Если старая Ollama не сообщает кеш, он неизвестен, а prompt-speed использует
prompt_eval_count; это отмечено в prompt_rate_basis. Полностью кешированный prompt
не получает выдуманную скорость. Короткий prompt даёт менее устойчивый замер prefill.

## Context limit отдельно от токенов

**Выбранный контекст — лимит окна, не длина prompt.** K = 1024 токена; 32K по умолчанию.
В таблице отдельно: фактический лимит,
входные токены, обработанные, кешированные и выходные токены.
Ollama получает выбранный `num_ctx` в каждом запросе, включая прогрев.
llama.cpp задаёт лимит при запуске сервера. Если внешний сервер использует другой
контекст, тест не начинается: интерфейс сообщает фактическое значение и необходимость
перезапуска с `-c N -np 1` либо перехода в управляемый режим.
Важен лимит одного запроса, а не общий пул slots и не обучающий n_ctx_train.
Если лимит не сообщён сервером, он не считается подтверждённым и тест завершается
ошибкой. JSON хранит отдельно `requested_context` и фактический `model_info.context_limit`.

## Вкладка «Модели»

- **Ollama:** имя/тег, размер, квант и дата из API. Удаление — через `DELETE /api/delete`.
  Загруженная модель предварительно выгружается через `keep_alive: 0`; выгрузка проверяется.
- **GGUF:** только добавленные папки и отдельно выбранные файлы; полный путь, имя,
  размер, архитектура/имя модели и квант из metadata. Подпапки обходятся без перехода
  по ссылкам/junction; весь диск автоматически не сканируется. Неизвестный код кванта
  показывается как «тип N»; для загруженной управляемым сервером модели доступно
  уточнение кванта через его API. Повреждённый GGUF виден, но без недоступных metadata.
- Папку можно добавить или убрать из списка; это не удаляет её содержимое.
  Можно открыть папку выбранного GGUF в Проводнике и отсортировать модели по размеру.
- Перед удалением показываются имя и размер, а для GGUF — полный путь. Если модель
  загружена, подтверждение предупреждает о выгрузке. Файл, используемый внешним
  llama-процессом, не удаляется: сначала остановите этот процесс. LLM Meter управляет
  только собственным процессом. Изменившийся после обновления списка файл требует
  нового подтверждения. Удаляется ровно выбранный GGUF, без mmproj и соседних файлов.
- После удаления список обновляется, показываются размер удалённой записи и изменение
  свободного места на диске (если доступно). Общие слои Ollama могут сохраняться для
  других тегов: сумма размеров тегов не равна физически занятому/освобождённому месту.
  Для удалённого Ollama размер освобождённого места не выдаётся за известный.

## Память и offload

Для строк размещения в новых сборках включите подробность логов `-lv 4`.

Общие VRAM и загрузка GPU — nvidia-smi; системная RAM — Windows API. Это показатели
**всего компьютера**, включая другие программы. Для удалённого сервера местная
аппаратная телеметрия не используется. Без NVIDIA/nvidia-smi эти поля недоступны.

Ollama: GPU = size_vram; RAM ≈ = max(0, size - size_vram). Offload — доля памяти
по учёту Ollama, **не число слоёв**, не загрузка GPU и не рабочий набор процесса.

llama-server API не сообщает точного распределения модели в RAM/VRAM.
Можно выбрать **лог текущего запуска**: размеры CPU/GPU буферов весов и строка
offloaded X/Y layers to GPU. KV/compute не прибавляются; Host-буферы относятся к RAM.
Это выделенные/отображённые буферы, не рабочий набор процесса. Число слоёв не выдаётся
за долю памяти. Проверяется последняя загрузка и совпадение пути модели с /props.
Свежесть лога нужно проверить самостоятельно: одна модель могла перезапускаться
с другими настройками. Без подходящего лога поля неизвестны. Квант не угадывается
по имени файла. Различающиеся источники/определения памяти сохранены в отчёте.

GPU опрашивается примерно раз в секунду. Для каждого устройства показаны среднее
по доступным снимкам и пик за тест, включая прогрев. JSON также содержит пик общей
VRAM и статистику только внутри измеряемых запросов (measured_gpu_summary).
Отсутствующие измерения не считаются нулями; всплески между снимками могут быть пропущены.

## Отчёты и проверки

JSON сохраняется в results/ по общей схеме schema_version=2: backend, модель,
версия, метаданные с источниками, context limit, счётчики, замеры, медианы и телеметрия.
Старые отчёты не меняются. Статусы cancelled/error не получают итоговые медианы.
Остановка прерывает поток; лимит запроса — 300 секунд. Ollama держит модель до 2 минут;
время жизни llama.cpp управляется сервером. Другие модели не выгружаются автоматически.
Для сравнения используйте одинаковые context limit, квант, thinking, питание и нагрузки.

Проверки: `python -m unittest discover -s tests -v` из папки измерителя.

Источники: [Ollama generate](https://docs.ollama.com/api/generate),
[Ollama ps](https://docs.ollama.com/api/ps),
[llama-server API](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md).
