# Реализация Модельной студии

24 сентября 2026. Основание: [архитектура](ARCHITECTURE.md), [макеты](design-v2/README.md).

## Реализовано

- Пять разделов Qt Quick: запуск/ручные параметры/работающая сессия; чат; библиотека моделей; быстрый тест/исследование/история; настройки.
- Общая сессия для Ollama и llama.cpp: управление собственным сервером, проверка готовности и контекста, отмена, выгрузка. Внешний процесс не считается собственностью приложения.
- Черновик запуска отделён от фактической сессии. Смена конфигурации работающего сервера требует явного действия.
- GGUF/Ollama-каталог, поисковые списки, системный выбор файла/папки, SHA-256 в фоне, архив и сохранение истории при удалении весов. Вспомогательные mmproj не предлагаются для запуска. Существующие runtime-профили импортируются и назначаются модели через интерфейс.
- Встроенный потоковый чат с PNG/JPEG-вложениями, свёрнутое reasoning, остановка, сохранение частичного ответа и локальная история. Перед запросом проверяется консервативная оценка размера истории с резервом ответа.
- OpenCode запускается отдельно для выбранного проекта. Подключение формируется из действующей сессии; глобальные и проектные файлы пользователя не перезаписываются.
- Один измерительный runner, компактная история в SQLite, TXT/JSON-экспорт по команде, самостоятельный технический отчёт в буфер, кнопка папки отчётов.
- Исследование с ограничением времени/числа конфигураций: базовый замер, допустимые MTP/Draft, контексты, условные KV-варианты; сохранение шагов, отмена, явное продолжение, восстановление исходной сессии.
- Рекомендации требуют проверенного артефакта, окружения, методики и фактических параметров. Для рекомендации большого контекста нужен длинный вход без усечения.
- Раздельные показатели GPU устройства, RAM системы и буферов/offload модели, с указанием источника. Неизвестное не подменяется нулём.
- Миграции БД, повторяемый импорт прежних данных, резервное копирование/восстановление, блокировка второго экземпляра с той же БД, восстановление статусов после аварийного выхода.
- Готовая Windows folder-сборка с Python/Qt; переносима вместе с `_internal`.

## Уточнения к архитектуре

1. **SQLite:** Python 3.14.7 поставляет SQLite 3.50.4. Для версий до 3.51.3 используется rollback journal (`DELETE`), для исправленных — WAL. Короткие транзакции и отдельные соединения сохранены.
2. **Сборка:** применён закреплённый PyInstaller вместо первого кандидата `pyside6-deploy`: в окружении нет C-компилятора/Nuitka. Проверен standalone-каталог; это сборка разработчика без подписи/установщика. Подробности в [BUILD.md](BUILD.md).
3. **Перенос:** `engine.py`, `llama_cpp.py`, `inventory.py`, `runtime_profiles.py` остаются общими транспортными/измерительными адаптерами. Старый Tk-интерфейс доступен через `launch.pyw` для проверки миграции; обычный `Запустить.pyw` открывает новую студию. Это сознательная временная точка возврата, а не второй новый runner.
4. **Границы проверки:** реальный запуск и короткий benchmark проверены на указанной модели. Полное исследование 96K–128K и MTP всех установленных сборок не прогонялось на GPU в рамках приёмки; алгоритм и остановка/восстановление покрыты интеграционными тестами. Длинная проба сейчас ограничена 131072 входными токенами; большее окно можно запустить, но оно не получает неподтверждённую рекомендацию.
5. **Внешние клиенты:** приложение не может запретить запросы стороннего OpenCode к серверу. Перед исследованием пользователь подтверждает, что завершил внешнюю работу. Прокси ради телеметрии не добавлен.
6. **Область чата:** текст, доступное reasoning и PNG/JPEG-вложения. Совместимый mmproj назначается явно; поддержка изображений проверяется через API работающего сервера. Инструменты и автоматическое сжатие истории не входят в эту версию. Изображения хранятся отдельно, сообщения содержат переносимые ссылки; `.studio-backup` включает БД и связанные файлы.

## Организация работы

Три ограниченных направления реализованы агентами GPT-6 Sol: сессия/backend; хранилище/каталог/исследование; QML-представление. Главный исполнитель согласовал контракты, связал Qt с ядром, проверил стыки, исправил найденные расхождения и проверил приложение целиком. Модели не запускались параллельно ради ускорения разработки.

- Реальный лог исследования подтвердил остановку до первого замера: запрос 100000, фактический контекст llama.cpp 100096. Управляемая сессия теперь принимает ограниченное округление вверх (до 255 токенов), сохраняет оба значения и их источник; уменьшение окна и произвольное расхождение отклоняются. Для внешнего llama.cpp и Ollama остаётся строгое сравнение. Это исправление проверено тестами; повторный живой прогон остаётся за пользователем, чтобы не прерывать его работу.
- Ошибка исследования и ошибка восстановления сессии обе показываются пользователю; причина завершения доступна в истории заданий.

### Отчёты после импорта

История автоматически выбирает первый видимый замер и снимает выбор, если фильтры его скрыли. Кнопки копирования/экспорта доступны сразу при наличии результата. Старые результаты без model_id сопоставляются по точному locator только для отображения (`display_model_id`); это не подтверждает digest и не делает их допустимыми для рекомендаций. В текстовый отчёт включены параметры и cases прежнего диагностического формата. SQLite-записи при отображении не меняются.

После исправления отдельно прошли 13 desktop-тестов и 12 research-тестов, QML lint и нативная проверка: авто-выбор → доступные кнопки → смена фильтра → снятие выбора → восстановление выбора. Копирование текста и запись JSON проверены на изолированных данных.

### Копирование нескольких отчётов

В истории доступны отдельный замер, все результаты выбранной модели по фильтрам и исследование целиком. Сводный текст содержит краткое сравнение и полные технические отчёты каждого замера. Для задания добавлены план, состояние и причины ошибок; незавершённый прогон помечен как снимок уже сохранённых результатов. Копирование задания включает ошибочные замеры независимо от фильтров списка. Ограничение загрузки строк интерфейса не ограничивает сводный отчёт: чтение и форматирование выполняются в worker, запись буфера — в Qt-потоке.

Нажатие на задание показывает его замеры и выбирает соответствующую модель без запуска сервера. Контексты и счётчик учитывают выбранное задание; числовые показатели в списке округлены для читаемости, исходная точность в отчётах сохранена.

Столбцы скорости, TTFT и статуса имеют фиксированные границы и обрезку слишком длинного текста. На изолированном Qt-окне проверены исходные значения с длинной дробной частью: `80,30 ток/с`, `2,698 с` и «Сохранён» занимают отдельные непересекающиеся области.

### Запуск и видимость рекомендаций

Обнаружены две базы из-за перенаправления AppData дочерних процессов MSIX-хоста: старая копия в контексте Codex и обычная база Windows с завершённым исследованием. `tools/start_windows.ps1` открывает установленное приложение через Проводник и существующий ярлык, сохраняя обычный контекст данных. Проверка на изолированном снимке настоящей базы (22 результата, 7 новых замеров) подтвердила доступность всех трёх рекомендаций. Повторные GPU-тесты и изменение результатов не потребовались.

Карточки запуска теперь показывают фактическую причину недоступности из расчёта рекомендаций вместо универсального «модель ещё не исследована». Скорость и остальные числовые показатели округлены только при отображении.

### Ручные параметры runtime и изображения

При загрузке каталога worker проверяет `llama-server --help`: полный флаг `--reasoning` включает выбор рассуждений, пара `--cache-type-k`/`--cache-type-v` — выбор KV-кэша. Объявленные профилем возможности, включая MTP, сохраняются. Проверка не загружает модель, ограничена пятью секундами и не открывает консоль; результат кэшируется по пути, размеру и времени изменения EXE. Это подтверждает поддержку параметра сервером, а не качество каждой конфигурации модели. Для смены модели черновик reasoning/KV возвращается к безопасным значениям по умолчанию.

Переключатель изображений без назначенного mmproj открывает системный выбор файла. Единственный найденный вспомогательный GGUF предлагается в диалоге, подключение требует выбора пользователя. Отмена оставляет изображения выключенными; назначение сохраняется для выбранной модели. Совместимость и поддержку vision по-прежнему проверяет запуск runtime.

Проверены обе установленные сборки llama.cpp через `--help`; обе поддерживают reasoning и KV. На изолированной копии данных Qt-проверка переключила reasoning в `off`, KV в `q8_0` и отменила диалог mmproj без ложного включения. 115 тестов: 114 успешно, один opt-in live-тест пропущен. Тест запуска проверяет передачу `--reasoning off` и обеих cache-type опций. Сохранённые замеры продолжают сопоставляться при изменении метаданных о доступных возможностях runtime.

### Бюджет рассуждений

В ручном запуске доступны Off / 2K / 4K / 8K / Auto и прежний On без лимита. Числовые варианты соответствуют 2048 / 4096 / 8192 токенам рассуждений. Они требуют обнаруженных `--reasoning` и `--reasoning-budget` у управляемого llama.cpp; сервер получает `--reasoning on --reasoning-budget N`. Auto сохраняет выбор шаблона модели, Off выключает рассуждение. Общий лимит выходных токенов клиента остаётся отдельным ограничением и включает рассуждение.

Ollama и внешние серверы не получают неподтверждённых числовых параметров. Недоступные пункты видны, но заблокированы; обработчик и конфигурация повторно проверяют поддержку. Бюджет сохраняется в конфигурациях, планах исследования и отчётах, учитывается при сопоставлении замеров. Старые записи без поля означают отсутствие числового лимита. Выбор Off/Auto/On и применение старой рекомендации очищают ранее выбранный бюджет.

Проверено: 118 тестов, 117 успешно и один opt-in live-тест пропущен; QML lint — код 0. Изолированное Qt-окно проверило все шесть вариантов, отключённые пункты и защиту от их активации, а также прежние KV/vision элементы. Передача числового флага серверу и отсутствие флага для старого режима покрыты тестом запуска. Реальный GPU-прогон для измерения длины reasoning не выполнялся.

Проверено: 111 тестов, 110 успешно и одна opt-in live-проверка пропущена. QML lint завершился с кодом 0; сохраняются предупреждения о неквалифицированных обращениях и размерах элементов layout. Изолированное Qt-окно подтвердило доступность кнопок и синхронизацию выбора при фильтрации. Тесты сводного отчёта покрывают незагруженные строки, границы фильтров, ошибки, неполные задания и устаревший ответ worker после снятия выбора. Пользовательское приложение для этих проверок не перезапускалось.

### Статус сессии, причины рекомендаций и имена моделей

Опрос продолжается после потери соединения. Возврат в `ready` требует ответа runtime и повторной проверки контекста: для Ollama проверяется наличие выбранной модели в `/api/ps`, для внешнего llama.cpp при восстановлении повторяется `prepare`. Выгруженная модель и изменённый контекст имеют отдельные состояния `model_unloaded` и `context_changed`; фактический контекст не подменяет запрос. Опрос не загружает модель и не выполняется во время операций. Отсоединение от Ollama с изменёнными извне настройками не выгружает чужую конфигурацию.

Сохранённые пять замеров Ornith подтвердили скорость, но не длинный вход: текущая `_long_context_probe` реализована только для llama.cpp. Поэтому рекомендации максимального контекста и баланса для этих данных недоступны. Карточки истории теперь явно объясняют это ограничение. Поддержка длинного входа Ollama этим изменением не добавлена; повтор идентичного прогона не устраняет ограничение. Пользовательские результаты не переписываются.

В «Модели» добавлены «Переименовать» и возврат исходного имени. `Store.rename_model` атомарно сохраняет отображаемое имя и существующие настройки aliases; файл, тег, digest и UUID не меняются. Исходное имя видно отдельно. Qt-мост обновляет подписи без перезапуска модели и сброса черновика запуска; алиас сохраняется при повторном сканировании каталога.

Проверено: 125 тестов, 124 успешно, один opt-in live-тест пропущен. Проверки включают восстановление соединения, изменение контекста, внешнюю выгрузку, продолжение UI-опроса, сохранение/сброс имён после сканирования и неизменность связи с результатами. QML lint — код 0; отдельное Qt-окно на копии 34 пользовательских результатов проверило пояснения карточек, диалог имени и статус контекста. Windows-сборка и изолированная проверка запуска EXE прошли. Работающий пользовательский runtime в проверках не перезапускался.

### Контекст Ollama при работе через OpenCode

Устранён фактический сброс 64K → 32K при первом запросе OpenCode: перед передачей подключения создаётся принадлежащий сессии профиль Ollama с закреплённым `num_ctx`, проверяется через `/api/show`, загружается и проверяется через `/api/ps`. Все клиенты сессии используют один runtime-тег; исходный тег и UUID каталога сохраняются. Профиль скрыт в каталоге, переиспользуется при повторном открытии OpenCode и удаляется при штатном завершении. Полный протокол и ограничение очистки после аварии описаны в OPENCODE.md.

Для OpenCode V2 явно указан пакет провайдера, чтобы новый профиль работал до завершения фонового обнаружения. Стабильный ключ каталога с `modelID` на текущий профиль сохраняет возможность продолжать диалог после нового запуска студии. Проверены сценарии ошибки создания, освобождение операции, сохранение исходного runner, очистка и передача подготовленного профиля из Qt-моста.

Проверено 129 тестов: 128 успешно, один прежний opt-in тест регистрации реальных провайдеров пропущен; установленный OpenCode v2.0.15 проверен на изолированном HTTP-сервере двумя сообщениями с продолжением диалога после пересоздания профиля. Дополнительно на настоящей Ollama 0.34.3: профиль Ornith сохранил исходные веса/шаблон/настройки источника, а два реальных OpenAI-совместимых запроса оставили фактический контекст 65536 и статус ready. Перед GPU-проверкой `/api/ps` был пуст; созданный тестом runner выгружен, его профиль удалён. Сохранённые пользовательские замеры не изменялись.
